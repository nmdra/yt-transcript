# SponsorBlock integration contract

Read this file before implementing SponsorBlock lookup, filtering, configuration, worker wiring, metadata, or formatter context in [Plan.md](Plan.md). This file owns those contracts. No live API queries have been run for the user's videos.

## Goal and confirmed choices

Use community segment timestamps to remove clearly covered caption cues before Pi formatting and from deterministic MCP output. CLI filtering remains opt-in; MCP attempts filtering by default and falls back to complete captions when it cannot apply it. Preserve the full `--raw` body and raw VTT bytes. The user selected removal of covered cues and **keeping captions with a visible warning if lookup fails**.

Keep MCP limited to one `get_transcript` tool, with required URL and optional deterministic `mode='filtered'`. The only modes are filtered/full. Omitted mode equals filtered, which tries SponsorBlock unless server configuration explicitly disables it. No data, disabled lookup, or lookup/data failure returns complete captions instead of a mode/configuration error. Full always skips SponsorBlock. CLI filtering remains disabled by default. Pi editing is never available through MCP.

## Configuration and CLI

Add a frozen `SponsorBlockConfig` in `config.py` and a defaulted `AppConfig.sponsorblock` field. Preserve all pending configuration-example work. Add this table:

```toml
[sponsorblock]
# Optional override. Omit for CLI-off / MCP-filtered-on defaults.
# enabled = false
categories = ["sponsor", "selfpromo", "interaction"]
timeout_seconds = 10
```

- `enabled`: optional strict boolean in TOML. Internal `SponsorBlockConfig.enabled` defaults to None to preserve unset versus explicitly disabled. Resolve unset to false for ordinary CLI and direct service calls, and true for MCP filtered mode. Explicit false disables lookup and makes MCP filtered return complete captions; explicit true enables it. Full mode always resolves false. Convert the resolved policy to a strict boolean before transport or private-worker serialization; never accept a TOML/private-request null value. This context-specific default preserves CLI behavior while providing the requested MCP default.
- `categories`: nonempty list of unique strings. Initially allow `sponsor`, `selfpromo`, `interaction`, `intro`, `outro`, and `preview`. Default to the first three. Reject unknown/duplicate categories. Keep `filler`, music categories, POIs, full-video labels, and community chapters out of this first release. Greeting deletion still comes from focused editorial instructions; do not assume intro-animation segments identify greetings.
- `timeout_seconds`: integer 1 through 30; default 10. This is a socket-operation timeout, not a promised total workflow deadline. MCP retains its existing 300-second operation deadline.
- Add mutually exclusive `--sponsorblock` / `--no-sponsorblock` flags using a nullable default so explicit CLI overrides the selected TOML. No arbitrary endpoint, API key, credentials, voting, submission, or persistent cache setting.
- Configured/explicit enablement affects cleaned Markdown, CLI preview, and MCP. In `--raw`, perform the opted-in lookup and compute the projection for consistent source metadata, but emit the original full body. Thus raw can incur the explicitly enabled lookup but never filters text.
- Raw VTT skips lookup and remains byte-identical. Reject explicit `--sponsorblock` with raw VTT; a saved enablement is ignored there. Permit `--no-sponsorblock` to disable lookup in ordinary modes. Doctor/MCP startup reject CLI SponsorBlock override flags; MCP policy uses its filtered default and validated TOML overrides. Doctor/help/version remain offline.
- The complete-example test must validate nested `SponsorBlockConfig` fields separately, not compare flattened TOML keys against flat `AppConfig` fields.

## Read-only bounded API client

Implement `lookup_sponsorblock(video_id, *, config, duration_seconds) -> SponsorBlockLookup` in new `sponsorblock.py`. Add immutable `SponsorBlockSegment(start_ms, end_ms, category, votes, locked)` and `SponsorBlockLookup` types matching the manifest below. Use a standard-library HTTPS client and an injectable transport seam; add no runtime dependency.

1. Disabled returns a fixed disabled result without creating a transport or doing DNS.
2. Compute SHA-256 of the validated ASCII video ID. Send only its first four lowercase hex characters in the path. Set `categories` to a JSON array encoded as a query value, `actionTypes=["skip"]`, and `service=YouTube`. Match the actual requested ID in the returned buckets. Never fall back to sending the full ID.
3. Make one GET attempt to the fixed official HTTPS endpoint. Verify TLS, reject redirects, send only a static product/version User-Agent and JSON Accept header, and send no cookies, credentials, referrer, or YouTube metadata. Do not submit, vote, report views, or preflight the server.
4. Read at most 512 KiB of response body and reject oversized data. Bound the top-level list to 512 buckets and the matching bucket to 256 segments. Perform strict UTF-8/JSON parsing. Discard unrelated video buckets and all unneeded fields, including descriptions and user IDs. Never log response bodies or request URLs.
5. HTTP 404, an empty valid response, no matching ID, or an empty eligible matching list means `not_found`, with no warning. It means no selected segments were returned, not that the video contains no promotion.
6. Expected timeout/network/TLS/HTTP errors other than 404, oversized bodies, malformed relevant data, ambiguous duplicate matching buckets, invalid times, and unverified/stale duration produce `lookup_failed`, a static reason code, empty usable segments, and the agreed visible warning. Never convert cancellation/KeyboardInterrupt into a fallback.
7. Normalize eligible `skip` segments to integer milliseconds. Require finite numeric times, reject booleans, require `0 <= start < end`, and require bounds inside known current duration. Accept only configured categories and nonnegative integer vote counts. Ignore other action types, unselected categories, and negatively voted entries; do not interpret points or full labels as intervals. Invalid eligible rows fail the whole lookup instead of applying a partial suspect set.
8. Require known, positive current duration and known, positive `videoDuration` on each eligible row. Reject a mismatch greater than one second as stale; zero/unknown cannot verify alignment. Keep all captions and warn when alignment cannot be verified. Even matching durations cannot detect an equal-length video edit.
9. Sort accepted intervals deterministically. Retain separate category/range records for source metadata; merge overlapping or touching intervals only in the internal removal mask. Do not copy arbitrary API descriptions into chapters or prompts.

## Filtering and chapter interaction

Use the existing single extraction and `clean_vtt_timed` output. Perform rolling cleanup globally **before** SponsorBlock filtering. Keep both full fragments/full body and an effective projection. Define frozen `AnnotatedCue(Cue)` with a default-empty `sponsorblock_overlaps` tuple; inherited times/text stay unchanged. Add `project_sponsorblock(fragments, lookup) -> CaptionProjection`, containing retained annotated fragments, original cleaned-fragment indices, removed-fragment indices/count, and the final lookup/filter result (which can become failure on all-removal). Chapter sections carry their timed fragments and derive joined text, so overlap context survives grouping without duplicating text in Pi payloads.

- Remove a retained fragment only when its complete original cue interval is contained within the selected interval union. Keep zero-duration cues and every cue that merely intersects a boundary. Do not trim words using a guessed percentage, split a mixed cue, or add omitted-text prose.
- Preserve caption input order and every unremoved token. Do not run cleanup again after removal; that can change overlap decisions or intentional repetitions.
- If the mask would remove every cleaned word, apply no removal, return `lookup_failed` with `REMOVAL_WOULD_EMPTY`, and warn. Preserve the fully validated source segments so their receipts can say `not_applied`; discard only the removal decision. This is the sole failure case permitted to retain usable segment records. Raw metadata-only output uses the original lookup and an unfiltered receipt, not an unused filter failure. Do not publish a silently empty deterministic document.
- Apply chapter grouping to effective fragments for Markdown/MCP. Keep supplied chapter metadata complete. Chapters with no retained captions have no body section. `--raw` still emits full unfiltered text.
- Keep community segment labels separate from YouTube chapter titles. Add overlap context to boundary-crossing retained fragments for focused Pi: selected category, normalized interval, and `boundary_overlap=true`. This is untrusted evidence, not proof that the whole fragment is an ad.
- Standard mode preserves every retained fragment. Focused may remove a clearly separable non-substantive boundary passage under its conservative rules; a brand name, category, or chapter title alone cannot authorize deletion.
- Cue-level containment intentionally leaves some promotion at boundaries. More accurate timestamp guidance does not establish word-level or semantic correctness.

## Shared service, metadata, and MCP

- Extend `fetch_clean_transcript` with optional `SponsorBlockConfig`; default disabled for existing callers. Store full body/fragments, effective body/fragments, chapter sections, lookup result, and safe warnings in `CleanedTranscript` using defaulted additions. Its `body` and default `document()` remain full/raw-compatible; formatter/MCP explicitly select the appropriate full/effective projection and removal receipt.
- CLI emits a static stderr warning once when enabled lookup/filtering cannot be used: `warning[SPONSORBLOCK_UNAVAILABLE]: SponsorBlock filtering was not applied; source captions were kept.` In focused mode, subsequent model editing can still remove non-substantive text; the warning refers only to deterministic SponsorBlock filtering.
- Add a default-disabled SponsorBlock lookup field to `VideoMetadata` for source facts. Keep that original lookup intact; pass the selected projection's result/receipt explicitly to serialization. Raw uses the source lookup with a not-applied receipt. Filtered uses the applied or fallback result. This makes serializers agree for one output without forcing false cross-mode header equality. Append a `sponsorblock` object after the original ten metadata fields and two chapter fields. Define typed nested results with exactly: `enabled`, `status`, `categories`, `segments`, `warning`, `reason_code`, `source`, `license_url`, `changes`, `removal_applied`, `removal_stage`, `removed_cue_count`, and `retained_overlap_cue_count`. Status is `disabled`, `available`, `not_found`, or `lookup_failed`. Each usable segment has `category`, `start_seconds`, `end_seconds`, `votes`, `locked`, `removal_status`, `removed_cue_count`, and `retained_overlap_cue_count`. Removal receipts follow the rules below.
- Require `warning`, `reason_code`, `source`, `license_url`, and `changes` to match controlled literal values at the service-result boundary; never allow a raw provider failure to become a free-text warning. Use static source attribution `SponsorBlock community data (https://sponsor.ajay.app)` and the license URL. `changes` states that records were selected and time-normalized; disabled mode has no contributed records. Do not include API bodies, unrelated video IDs, descriptions, or source exception text. Lookup status is separate from actual removal; available data alone must not mark anything removed.
- Keep video/chapter/lookup facts independent of Pi editing, but make receipts describe the selected output/input projection. Raw and filtered headers can now differ in receipt fields; this deliberately supersedes the earlier cross-mode byte-equality requirement. Metadata remains Python-owned. For identical source snapshots and actual receipts, standard/focused/MCP headers match. Separate live lookups may return different votes or segments.
- MCP supports `get_transcript(url, mode='filtered')` with only filtered/full. Filtered attempts lookup unless explicitly disabled; it returns complete captions when lookup is disabled, has no usable segments, fails, or cannot safely remove cues. Expected lookup/data failures retain the static warning, while intentional disablement and no returned segments need no failure warning. Full disables lookup/filtering regardless of server settings. Categories and timeout remain server-controlled. The private request carries URL, explicit filtered/full enum, and a resolved three-key SponsorBlock object with strict boolean enabled. Validate the enum/policy again in the worker; full must force disabled even if a private policy requests true. Keep existing limits. Only invalid arguments/configuration or caption/runtime failures remain errors; SponsorBlock unavailability is not a transcript error.
- On fallback, MCP returns complete deterministic captions with chapter headings or inline timestamp blocks. Lookup/data failure supplies the static warning/reason in metadata; intentional disablement and no segments supply no failure warning. This is successful usable output, not a tool execution error. Stdio stdout remains protocol-only. If the complete result exceeds size limits, retain the existing safe error rather than dropping metadata or captions.

### Controlled manifest values

- `warning` is null for disabled/available/not_found and is the exact static CLI warning line above for lookup_failed. Never attach exception text.
- `reason_code` is null for disabled/available/not_found. For lookup_failed, use exactly `LOOKUP_FAILED` for network/TLS/timeout/non-404 HTTP failure, `RESPONSE_TOO_LARGE` for body/bucket/segment caps, `INVALID_RESPONSE` for encoding/JSON/schema/eligible-row errors, `ALIGNMENT_UNVERIFIED` for unknown/stale duration, or `REMOVAL_WOULD_EMPTY` for filter rollback.
- `source` is `SponsorBlock community data (https://sponsor.ajay.app)` and `license_url` is `https://creativecommons.org/licenses/by-nc-sa/4.0/` when validated segments are published; otherwise both are null. `changes` is `Selected and time-normalized segment records; caption removal is reported separately.` for those published records and null otherwise. All three values are controlled literals, including on rollback with retained valid records.
- Counts are nonnegative integers, never booleans. Resolve disabled/full policy to enabled=false in the public manifest; enabled filtered lookup remains true even when it fails or yields no data. Strict private policy objects always carry a resolved boolean, not the configuration's unset sentinel.

## Actual removal receipts

Add frozen `SegmentRemovalReceipt` and `SponsorBlockRemovalReceipt` in `sponsorblock.py`. Compute them from original nonempty timed fragments, the exact removal mask, and the projection actually used, not from lookup availability or a model's claim.

- Top-level `removal_applied` is true only if at least one source fragment was removed for this output/input. `removal_stage` is `source_filter` when true and `none` otherwise. Aggregate counts use unique fragment indices; do not sum per-segment counts because intervals can overlap.
- Per-segment `removal_status` is `removed` when at least one matching fragment was removed and none overlapping it remain; `partial` when some were removed and some overlapping fragments remain; `kept` when matching fragments remain and none were removed; `no_matching_captions` when the interval matches no retained source fragment; and `not_applied` when filtering was not selected or was rolled back.
- Attribute a removed fragment to every eligible source interval it positively overlaps, even when union containment across adjacent intervals enabled removal. Count overlapping zero-duration cues as retained points when their timestamp falls in the half-open segment interval.
- Raw output always uses a not-applied receipt, even when it queried segment metadata. Disabled lookup, lookup failure, and all-removal rollback have zero aggregate removal counts. Do not claim removal based on a computed-but-unused projection.
- On raw/not-applied paths, removed counts are zero and retained-overlap counts reflect the original fragments when valid segment details exist. On applied paths, counts reflect removed versus kept fragments. `removed` means matching caption fragments were removed, not guaranteed removal of every spoken promotional word.
- Pi receipts describe deterministic removal from Pi's source input. They do not attribute later focused-model edits to SponsorBlock or claim that every sponsor phrase disappeared from generated text. MCP has no model stage, so its receipt describes the returned caption body directly.
- Add optional result/receipt keywords to `metadata_mapping`, `format_transcript_file`, and `CleanedTranscript.mapping/document`. Compute and store the unfiltered receipt from the full timed fragments in `CleanedTranscript`; its mapping/document defaults use that accurate raw receipt. The low-level serializers may default to zero counts only when no segment records exist; require an explicit computed receipt when segment records exist, rather than inventing retained-overlap counts from metadata alone. CLI raw explicitly uses the raw receipt; CLI Markdown and MCP pass the receipt for their selected projection. Preserve source lookup data in `VideoMetadata`; do not mutate it to match an arbitrary body's text.
- Validate all enum/boolean/count fields. Test overlapping interval attribution, partial boundary retention, no-match, raw/full, failure/rollback, and omitted versus explicit filtered selection, full override, and explicit server disablement. YAML and structured metadata must have identical receipts for one result.

## Formatter and preview context

Generalize the proposed chapter-only types to `ContextChunk`, `ContextFormattingPlan`, and `plan_context_formatting`. Keep `plan_transcript_formatting` as the shared dispatcher.

- Use the old plain-text planner when no chapter or SponsorBlock boundary context is needed.
- Otherwise serialize only relevant chapter/fragment/segment context and retained source text. Each source word appears once. The entire serialized stdin payload counts toward `chunk_chars`. Repeat small context for continuations, not captions.
- Carry timing/overlap annotations through chapter sections, rather than flattening before their mapping is complete. Use optional canonical chapter headings; a SponsorBlock-only payload without YouTube chapters does not invent a `Transcript` chapter or impose chapter-header validation.
- Standard's system prompt remains unchanged. Use a fixed source-data framing append instruction for contextual JSON; focused receives the same framing plus its separate editorial system prompt.
- Preview uses the exact effective projection/context plan and reports lookup status, warning, removed-cue count, retained-input characters, editorial mode, and planned calls. Keep the original full cleaned-character count distinct. No Pi invocation occurs.
- Removing cues can reduce calls; context overhead can increase them. Report the computed count, not a promised saving. Fallback plans from complete retained source, so cap checks reflect the real run.

## Verification seams

Use synthetic API responses and local fake transports, never SponsorBlock queries in offline tests.

- Exact hash-prefix URL/query construction; no full-ID URL; no request when disabled; fixed host/TLS/redirect behavior; one attempt; timeout/body limits; UTF-8/JSON errors; 404/no match; hash-bucket collisions; duplicate matching buckets; unrelated descriptions never retained.
- Eligibility and invalid-data fallback: categories/actions/votes, locked boolean or 0/1, fractional/NaN/infinite/boolean times, overlaps, known/missing/stale durations, and caps. Expected failures warn; cancellation propagates.
- Removal: whole contained cues, crossing/zero-duration cues, adjacent/overlapping segment union, rolling overlaps across removed regions, manual repetition, all-removal fallback, gaps, chapters emptied by removal, and full raw/VTT preservation.
- Service/CLI/MCP: one YouTube extraction plus at most one lookup under the resolved CLI/MCP policy; visible fallback warning and typed metadata; raw metadata lookup without body filtering; no Pi in MCP; strict private policy fields; source-field equality across shared snapshots with accurate mode-dependent receipts, and header equality only for identical receipts; UTF-8 size limits; stderr-only diagnostics and no provider errors/URLs leaking.
- Formatter: filtered/context-inclusive plan parity, preserved retained-word order, focused versus standard instructions, boundary evidence without blanket brand deletion, no extra model call, and correct cap rejection after either filtering or fallback.
